# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Manual shadcn-compatible canonical source, emitted as a static shadcn registry and byte-equivalent repository mirror |
| Preset | No root preset or `components.json`; the clean `fixtures/registry-vite` consumer uses shadcn `new-york`, `baseColor: neutral`, Tailwind v4, `cssVariables: true`, and `rsc: false` |
| Component library | Official shadcn primitives; Radix behavior is justified only for Dialog and Popover, with native HTML preferred elsewhere |
| Icon library | Injectable icon slots with exact `lucide-react@1.20.0` defaults in copied source |
| Font | Host-provided `--font-sans`; documented fallback `ui-sans-serif, system-ui, sans-serif` |

This is intentionally a manual design system rather than a root `shadcn init`. The repository is a registry author and headless package, not a shadcn application. Standard shadcn semantic variables are the customization boundary: `--background`, `--foreground`, `--card`, `--card-foreground`, `--primary`, `--primary-foreground`, `--muted`, `--muted-foreground`, `--border`, `--ring`, `--destructive`, and `--radius`. The root package must not gain UI runtime or peer dependencies.

The canonical UI is neutral and product-embeddable. It contains no Afferent logo, branded masthead, proprietary navigation shell, or router. Public surfaces use comfortable density; administrative surfaces use compact rows that remain readable and become labelled cards on phones.

### Visual hierarchy and focal points

| Surface | Primary focal point | Secondary hierarchy |
|---------|---------------------|---------------------|
| Feedback board | Ranked feedback list and the `Create feedback` action | Board selector, search, filters, and sort controls precede the list without competing with it |
| Feedback detail | Post title, status, vote action, and canonical content | Metadata and activity are quieter; discussion is the next semantic section |
| Roadmap | The three server-provided Planned, In Progress, and Complete groups | Board filter is compact and visually subordinate; group counts and cards preserve server order |
| Changelog | Entry title, publication date, and body | Linked feedback follows the editorial content as a secondary section |
| Notifications | Unread notification list | Unread count and mark-read actions support, rather than replace, the notification text |
| Admin | Selected feedback or changelog record in the detail workspace | The triage queue is the navigation context; dangerous actions are visually separated at the end |

Icons support text and never carry meaning alone. Every icon-only control has an accessible name, a visible tooltip or nearby text fallback, and a 44px coarse-pointer hit area. Decorative icons use `aria-hidden="true"`.

## Spacing Scale

Declared standard values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps and tight metadata separation |
| sm | 8px | Compact admin control gaps and inline padding |
| md | 16px | Default control groups, card padding, and mobile gutters |
| lg | 24px | Public card padding and section padding |
| xl | 32px | Screen section gaps and tablet gutters |
| 2xl | 48px | Major section breaks and desktop page gutters |
| 3xl | 64px | Top-level desktop screen rhythm only |

Exceptions: 44px minimum coarse-pointer control size and hit area is a sizing/accessibility exception, not a spacing token. The WCAG 2.2 AA minimum remains 24 by 24 CSS pixels or a documented criterion exception. One-pixel borders and two-pixel focus rings are rendering strokes, not layout spacing. No 12px, 20px, or 40px spacing token may be introduced.

Component density rules:

- Public cards use 24px internal padding on tablet/desktop and 16px at 320px.
- Admin rows use 16px vertical/inline padding; compact control groups use 8px gaps.
- Page-owned screens use 16px phone gutters, 32px tablet gutters, and at most 48px desktop gutters.
- Successive heading/content groups use 16px; independent sections use 32px; screen boundaries use 48px or 64px.

## Typography

Exactly four sizes and two weights are allowed throughout copied source:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label and metadata | 14px | 600 semibold for labels; 400 regular for metadata | 1.4 |
| Body and controls | 16px | 400 regular; 600 semibold for action text | 1.5 |
| Section heading | 20px | 600 semibold | 1.3 |
| Screen display | 28px | 600 semibold | 1.2 |

The allowed font weights are only regular 400 and semibold 600. Status, urgency, and selection must not be communicated by weight alone. Body copy is never reduced below 16px; 14px is reserved for labels, timestamps, counts, and secondary metadata. Long user-authored content wraps naturally with a readable maximum line length of 72 characters where composition permits.

## Color

The palette follows an explicit 60/30/10 hierarchy. Values are defaults expressed through shadcn variables; adopters may override the variables but are responsible for retaining 4.5:1 text and 3:1 non-text contrast.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)`; light `#ffffff`, dark `#09090b` | Page background and the majority of open visual area |
| Secondary (30%) | `var(--card)` / `var(--muted)`; light `#f4f4f5`, dark `#18181b` | Cards, queue rows, grouped roadmap sections, popovers, and subdued navigation |
| Accent (10%) | `var(--primary)`; light `#1d4ed8`, dark `#60a5fa` | Primary CTA, current selection indicator, unread marker, and focus ring only |
| Destructive | `var(--destructive)`; light `#b91c1c`, dark `#f87171` | Destructive buttons, destructive confirmation title/icon, and urgent destructive errors only |

Accent reserved for: the `Create feedback`/screen-primary CTA, the current board/filter/navigation selection, unread notification dots or count, and the visible keyboard focus ring. Ordinary links use underlined foreground text, secondary buttons use neutral borders, statuses use text plus neutral badge shape, and roadmap groups do not each receive a decorative color.

Supporting defaults:

| Token | Light | Dark | Contract |
|-------|-------|------|----------|
| `--foreground` | `#18181b` | `#fafafa` | Primary text, at least 4.5:1 against its surface |
| `--muted-foreground` | `#52525b` | `#d4d4d8` | Secondary text, at least 4.5:1 against muted/card surfaces |
| `--border` | `#71717a` | `#71717a` | Component boundaries and state outlines, at least 3:1 where meaningful |
| `--primary-foreground` | `#ffffff` | `#09090b` | Text/icons on the accent surface |
| `--ring` | `#1d4ed8` | `#60a5fa` | Focus indication; never removed without an equivalent visible replacement |

Error/destructive red is the only second semantic hue. Pending, success, roadmap status, and notification type remain understandable through copy, icons, structure, and neutral styling; color is never the sole signal.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Create feedback` |
| Empty state heading | `No feedback yet` |
| Empty state body | `Start the conversation by creating the first feedback post.` |
| Error state | `We couldn't load feedback. Try loading it again.` Action: `Try loading again` |
| Destructive confirmation | `Merge duplicate`: `Merge “{duplicateTitle}” into “{canonicalTitle}”? This moves its votes, comments, and history and cannot be undone. Type “{duplicateTitle}” to confirm.` |

All baseline English strings live in one complete typed dictionary, deep-merged once by `AfferentUiProvider`. Per-screen overrides replace individual keys without requiring a second full dictionary. Copy is product-neutral and does not mention Afferent unless the host chooses to do so.

### Required action labels

| Workflow | Required visible label |
|----------|------------------------|
| Create a post | `Create feedback` |
| Finish post creation | `Post feedback` |
| Edit a post | `Save feedback changes` |
| Vote / remove vote | `Vote for feedback` / `Remove feedback vote` |
| Comment / reply | `Post comment` / `Post reply` |
| Subscribe / unsubscribe | `Subscribe to updates` / `Unsubscribe from updates` |
| Pagination | `Load more feedback`, `Load more notifications`, or the domain-specific noun |
| Mark read | `Mark notification read` |
| Search recovery | `Clear feedback filters` |
| Admin update | `Save moderation changes` |
| Status transition | `Update feedback status` |
| Merge | `Merge duplicate` |
| Archive / restore | `Archive feedback` / `Restore feedback` |
| Tag creation / deletion | `Create feedback tag` / `Delete feedback tag` |
| Changelog draft | `Save changelog draft` |
| Publish / unpublish | `Publish changelog entry` / `Unpublish changelog entry` |

No primary or confirmation action may use `Submit`, `OK`, `Save`, `Create`, `Delete`, `Retry`, or `Cancel` by itself. Dialog escape actions use an outcome-specific label such as `Keep feedback`, `Keep tag`, `Keep changelog unpublished`, or `Return to editing`.

### Required empty, auth, redirect, and error copy

| State | Heading | Body / action |
|-------|---------|---------------|
| Board has no posts | `No feedback yet` | `Start the conversation by creating the first feedback post.` / `Create feedback` |
| Filters match nothing | `No matching feedback` | `Try a different search or clear the active filters.` / `Clear feedback filters` |
| Similar posts empty | `No similar feedback found` | `Continue creating your feedback post.` |
| Discussion empty | `Start the discussion` | `Be the first to add a comment to this feedback.` / `Post comment` |
| Roadmap group empty | `Nothing in {groupName}` | `Feedback will appear here when its status changes to {groupName}.` |
| Changelog empty | `Updates will appear here` | `Published product updates haven't been added yet.` |
| Notifications empty | `You're all caught up` | `New replies, status changes, and changelog updates will appear here.` |
| Admin queue empty | `No feedback to review` | `Feedback matching this queue will appear here.` |
| Loading | `Loading {domainNoun}…` | Announce once through the polite status region; skeletons retain labelled context |
| Unauthenticated | `Sign in to continue` | `Sign in through this application to {requestedAction}.` / host-injected `Sign in` link label |
| Not authorized | `You don't have access to this area` | `Ask an application administrator if you need feedback management access.` |
| Unsupported | `This feature isn't configured` | `The application needs to provide the required Afferent function references.` |
| Not found | `Feedback not found` | `It may have been withdrawn, archived, or made unavailable.` / `Return to feedback` |
| Merged | `This feedback was merged` | `Continue to the canonical feedback post.` / real link `View canonical feedback` |
| Query error | `We couldn't load {domainNoun}` | `Try loading it again. If the problem continues, contact the application owner.` / `Try loading again` |
| Mutation error | `{Action} wasn't completed` | Render the actionable typed headless message and a domain-specific retry or correction path |
| Rate limited | `Please wait before trying again` | Render the headless retry guidance without inventing a client timer |

### Destructive and consequential confirmations

| Action | Approach | Confirmation copy and actions |
|--------|----------|-------------------------------|
| Merge duplicate | Typed-name dialog; irreversible and high blast radius | Copy from the primary destructive contract; actions `Merge duplicate` and `Keep feedback` |
| Archive feedback | Plain confirmation dialog; reversible | `Archive “{title}”? It will leave public feedback views until restored.` Actions `Archive feedback` and `Keep feedback` |
| Withdraw own feedback | Plain confirmation dialog | `Withdraw “{title}”? It will no longer appear in public feedback views.` Actions `Withdraw feedback` and `Keep feedback` |
| Delete internal tag | Plain confirmation dialog | `Delete “{tagName}”? The tag will be removed from assigned feedback without deleting feedback.` Actions `Delete feedback tag` and `Keep tag` |
| Publish changelog | Plain confirmation dialog; editorial state is reversible | `Publish “{title}” now? It will become visible at its public changelog link.` Actions `Publish changelog entry` and `Return to editing` |
| Unpublish changelog | Plain confirmation dialog; reversible | `Unpublish “{title}”? Its public changelog link will stop showing the entry until republished.` Actions `Unpublish changelog entry` and `Keep changelog published` |

Dialogs restore focus to the invoking control, or to the next logical row/action if that control no longer exists. Destructive controls are grouped after ordinary editing controls rather than placed beside the primary save action.

## Component and Composition Contract

### Canonical source inventory

| Area | Required copied-source components | Contract |
|------|-----------------------------------|----------|
| Core | `AfferentUiProvider`, dictionary, icon slots, native link adapter, state regions, `cn` helper, token stylesheet | Deep-merge copy once; inject href/link/navigation/current location; never infer authority |
| Board | `AfferentBoardScreen`, board/filter controls, feedback list/card, composer, similar feedback, detail, vote/subscription, discussion, activity | Board-first responsive composition with real post links; consumes only Phase 2 hooks |
| Roadmap | `AfferentRoadmapScreen`, board filter, roadmap group, roadmap card | Renders exactly the Planned, In Progress, and Complete groups returned by the headless hook; never regroups locally |
| Changelog | `AfferentChangelogScreen`, chronological list/card, entry detail, linked feedback | Stable real links and server-provided chronological order |
| Notifications | `AfferentNotificationsPopover`, `AfferentNotificationsList`, notification row | Popover is optional composition; the full list remains usable independently and exposes mark-read state |
| Admin | `AfferentAdminScreen`, queue, detail workspace, moderation form, status/board/tag controls, activity, merge dialog, changelog editor | Queue/detail on wide screens, labelled cards on phones, keyboard-complete and server-capability driven |

Every file that imports or invokes a hook begins with an explicit `"use client"` directive before imports. Presentational leaf files may omit it only when they remain hook-free. Copied source imports headless behavior exclusively from `afferent/react.js`; it never imports Convex, an auth provider, a router, or a toast library.

The default link renderer emits a real `<a href>`. Host adapters may inject router-aware link and navigation behavior from a host-owned client module. Components never read `window.location`, time, randomness, viewport width, or media queries during render. CSS controls layout and reduced motion; React `useId` controls stable accessible relationships.

### Closed state mapping

Every screen exhaustively switches on the exported headless union and ends with a compile-time `never` guard. The copied UI renders loading, empty, unsupported/not-configured, unauthenticated, not-authorized, error, retry, ready, pending, merged, and not-found states. It must not collapse typed failures into a generic exception boundary.

Mutation controls read pending, typed error, reset, and optimistic state directly from the Phase 2 hook. They disable only conflicting actions, retain readable context, expose `aria-busy` where appropriate, and announce completion/error through stable live regions. The copied UI owns no second optimistic cache, generation, account identity, toast queue, or navigation side effect.

User-authored safe content is rendered as text or through a closed React-node renderer. `dangerouslySetInnerHTML`, executable URL schemes, and raw provider/component documents are forbidden.

## Responsive Layout Contract

CSS-first breakpoints are 640px (`sm`), 768px (`md`), 1024px (`lg`), and 1280px (`xl`). These are layout breakpoints, not render-time JavaScript branches.

| Width | Public surfaces | Administrative surfaces |
|-------|-----------------|-------------------------|
| 320–639px | One column, 16px gutters, filters wrap or disclose without horizontal page scroll, cards use 16px padding, roadmap groups stack as semantic sections | Queue and detail render one at a time through host-controlled navigation; table-like rows become labelled cards; every action remains present |
| 640–767px | One column with wider cards; board/filter controls may share rows when labels remain visible | Labelled cards remain primary; related controls may form two-column field groups |
| 768–1023px | List/detail may use a 40/60 split when both regions remain at least 320px; roadmap may become three columns | Queue/detail uses a 35/65 split; dialogs stay within viewport with internal scrolling |
| 1024px and wider | Content is centered with readable line lengths; board list/detail and three roadmap columns are simultaneous | Queue/detail workspace is simultaneous; compact rows retain labels and keyboard order |

At 200% browser zoom the composition must behave like its narrower equivalent without loss of actions or two-dimensional page scrolling. A local data region may scroll only when its semantic purpose requires it and has an accessible label; page-level horizontal scrolling is forbidden at 320 CSS pixels. Sticky controls use scroll padding and must never fully obscure keyboard focus.

No task requires drag-and-drop. Roadmap administration uses labelled status controls and buttons. Any future visual rearrangement must retain a non-drag action path.

## Accessibility and Interaction Contract

- Use native `header`, `nav`, `main`, `section`, `article`, `form`, `fieldset`, `legend`, `ol`/`ul`, `button`, `a`, `label`, `input`, `textarea`, and `select` semantics before ARIA.
- A page-owning screen provides a visible-on-focus skip link and exactly one `main`; embedded screens do not create duplicate page landmarks.
- Heading levels are ordered: screen title, feature sections, then card/detail subsections. Visual size never changes semantic order.
- All fields have visible labels, associated help/error text, and actionable validation messages. Placeholder text is never the label.
- Keyboard order follows DOM/read order. Enter/Space operate native controls; Escape closes Dialog/Popover; Dialog traps focus and restores it; Popover dismissal returns focus predictably.
- Focus indication uses a two-pixel `--ring` outline with offset and remains visible in forced-color modes. Reduced-motion users receive no animated translation or nonessential transition.
- Stable `role="status"`/`aria-live="polite"` regions announce loading completion, result counts, pagination, pending operations, and success without moving focus. `role="alert"` is reserved for errors requiring immediate correction.
- Touch targets are 44 by 44 CSS pixels for coarse pointers. Fine-pointer controls still meet WCAG 2.2 24 by 24 CSS pixels or document the spacing/equivalent exception.
- Links are distinguishable without relying on color. Statuses, unread state, selection, errors, and destructive state use text/icon/shape in addition to color.
- Host theme overrides are accepted, but documentation explicitly assigns the host responsibility for maintaining contrast and visible focus.

Acceptance evidence names these WCAG 2.2 criteria rather than claiming blanket certification: 1.4.3 Contrast (Minimum), 1.4.4 Resize Text, 1.4.10 Reflow, 1.4.11 Non-text Contrast, 2.1.1 Keyboard, 2.1.2 No Keyboard Trap, 2.4.3 Focus Order, 2.4.7 Focus Visible, 2.4.11 Focus Not Obscured (Minimum), 2.5.7 Dragging Movements, 2.5.8 Target Size (Minimum), 3.3.1 Error Identification, 3.3.2 Labels or Instructions, and 4.1.3 Status Messages.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | `button`, `badge`, `card`, `input`, `label`, `textarea`, `select`, `dialog`, `popover`, `separator`, `skeleton` | Official registry only; no third-party vetting required — 2026-07-17 |
| Afferent generated registry | `afferent-ui-core`, `afferent-board`, `afferent-roadmap`, `afferent-changelog`, `afferent-notifications`, `afferent-admin` | Project-owned canonical source; deterministic generation, schema validation, real local `shadcn add`, and byte-equivalence gate required |

No third-party registry is permitted in Phase 3. The Afferent registry is generated from repository-owned source and is not a third-party source. Exact copied-source dependencies are `class-variance-authority@0.7.1`, `clsx@2.1.1`, `tailwind-merge@3.6.0`, `lucide-react@1.20.0`, and `radix-ui@1.6.0`; exact build/evidence pins remain fixture/root dev tooling as recorded in `03-RESEARCH.md`.

The canonical files own explicit `"use client"` directives and import aliases. The generator stable-sorts item and file lists, rewrites declared aliases deterministically for the fixture, emits no timestamps, and produces:

- `registry/registry.json` and `registry/r/*.json` conforming to current official shadcn schemas;
- `examples/ui/afferent/**` byte-equivalent to the corresponding `ui/afferent/**` canonical files;
- a stable relative-path plus SHA-256 manifest for canonical/mirror drift detection.

Generated registry and mirror files are never hand-edited. CI regenerates twice, validates schemas, compares manifests/bytes, and fails on a tracked diff. Sibling Afferent item dependencies use explicit relative generated JSON addresses rather than bare names that could resolve to the official registry.

The distinct `fixtures/registry-vite/components.json` is pinned to Tailwind v4 with `style: "new-york"`, `baseColor: "neutral"`, `cssVariables: true`, `rsc: false`, an empty Tailwind config path, and deterministic aliases for `@/components`, `@/components/ui`, `@/lib`, `@/lib/utils`, and `@/hooks`. The root remains uninitialized.

## Verification Evidence Contract

| Contract | Executable proof | Stable release artifact |
|----------|------------------|-------------------------|
| Canonical registry/mirror | Generate twice; schema validate; compare canonical/mirror hashes and bytes; fail on diff | Stable manifest and generated registry catalog |

| Announcements and errors | Assert polite status updates and urgent alerts without focus theft | Criterion-named status/error evidence |
| Contrast | Compute text and non-text contrast for documented light/dark defaults without rounding thresholds | Normalized contrast report |
| Reflow and responsive layout | Run representative public/admin tasks at 320x800, 768x1024, and 1280x800; assert no page-level horizontal overflow | Stable phone/tablet/desktop captures plus 320px capture |
| Zoom | Run the same tasks at 200% browser zoom and assert all controls remain available | Stable 200% capture and task transcript |
| Hydration | Server-render and hydrate loading/auth/empty fixtures; fail on recoverable hydration errors or unequal first DOM | Deterministic hydration transcript |

Evidence normalization removes wall-clock timestamps, temporary paths, random ports, and browser process IDs. Manual/interaction fixtures are the primary accessibility evidence; axe complements rather than replaces them. Client-only public rendering and weaker SEO are documented v1 limitations. No initial-data or hydration-reconciliation API is introduced in this phase.
