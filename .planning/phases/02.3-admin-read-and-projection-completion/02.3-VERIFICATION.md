## Backend and Trust-Boundary Review

### Admin feedback and moderation

`listAdminFeedback` enforces `numItems` 1..50 and paginates `posts.by_scope_visibility_created` by `scopeId` plus `visibilityKey`, descending. `getAdminPost` uses `requirePostInScope`, so it can reach hidden/archived records without public-feed fallback while rejecting another scope. `listAdminFeedback`, `getAdminPost`, and `listAdminChangelog` derive scope, call `authorizeAdmin`, and only then call `runQuery`. The component remains host-auth agnostic.

`toAdminFeedbackPostDto` is the common projection for reads and edit/move/status/lock/archive/tag assignment returns. It exposes the unchanged public feedback DTO plus `discussionLocked`, `archived`, `active|withdrawn|merged` disposition, and optional canonical merge destination. No browser-supplied identity, scope, or authorization input reaches these reads.

### Changelog projection

`listAdminChangelog` paginates `changelogEntries.by_scope_created` in descending order with the same 1..50 guard and maps every row through `toAdminChangelogEntryDto`. The mapper loads at most the bounded link limit from `by_scope_entry_order`, follows same-scope redirects with a depth/cycle bound, removes duplicate canonical posts while preserving first order, and emits id/title/status summaries. The output DTO has `links`, not `postIds`; `postIds` remains only mutation intent for setting links.

### Activity projection

The common append path loads each optional board/tag/changelog referent and stores a nested snapshot only when it matches the activity scope. Projection prefers the snapshot, otherwise uses a live same-scope record, otherwise emits `Deleted board`/`deleted-board`, `Deleted tag`, or `Unavailable changelog entry`/`unavailable-changelog-entry`. Internal relation IDs remain in component storage but are absent from public activity row/page validators.

Automated key-link detection reported **5/6**, but its one miss is not a wiring failure. The plan pattern names obsolete flat fields (`fromBoardName|tagName|changelogTitle|changelogSlug`); implementation and schema use the locked nested forms `fromBoardSnapshot`, `tagSnapshot`, and `changelogSnapshot`. Manual inspection verifies the append-to-schema-to-projection link.
