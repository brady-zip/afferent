<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Server scope resolver → host client | Identity-derived scope is trusted only after server verification and one-way derivation. |
| Host client → component queries | Concrete scope and minimal actor facts enter the isolated data boundary. |
| Component document → public DTO | Internal IDs, scope, external identity, and provider/private data must be removed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-09 | Spoofing | scoped host client | critical | mitigate | Server-only resolver runs first on every operation; browser validators have no scope field. |
| T-01-10 | Information Disclosure | direct-ID guards | critical | mitigate | Scope recheck after load and identical structured not-found result for cross-scope/random IDs. |
| T-01-11 | Information Disclosure | paginator/indexes | high | mitigate | Scope-first index ranges, no post-page filtering, two-user reactive matrix on real Convex. |
| T-01-12 | Elevation of Privilege | installation configuration | high | mitigate | Independent host admin callback gates the narrow idempotent configuration intent. |
| T-01-13 | Tampering | author mutations | high | mitigate | Transactional scope and actor-ownership checks before validated edit/withdraw patches. |
| T-01-14 | Information Disclosure | DTO mapping | high | mitigate | Explicit validators/mappers and structural export tests forbid private/provider shapes. |
| T-01-SC | Tampering | npm dependencies | high | mitigate | Use only versions approved in Plan 01-01 and preserve lockfile integrity. |
