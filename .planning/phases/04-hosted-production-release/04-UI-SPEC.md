# Phase 4 — UI Design Contract

> Visual and interaction contract for the clone-and-run local application shell and sandbox lifecycle surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker, and updated by the 2026-07-30 local-demo scope pivot.

---

## Scope and Inheritance

Phase 4 does not redesign Afferent's product interface. Feedback, post detail, roadmap, changelog, notifications, and administration render the canonical Phase 3 source from `ui/afferent/**` through the generated registry and public `afferent/react.js` bindings. The local application adds only:

- the Afferent-branded application shell and route navigation;
- an explicit immutable-showcase versus private-sandbox boundary;
- Convex Auth sign-in, account, loading, and sign-out states;
- private-sandbox lifecycle, reset, expiry, quota, and recovery surfaces;
- a visible release-version link to the matching npm package and source tag.

Host-only shell code lives with the local Vite application. It must not be added to `ui/afferent/**`, the generated registry, or `examples/ui/afferent/**`, and it must not fork or restyle the internals of a canonical Phase 3 product screen. This contract supplements rather than replaces `03-UI-SPEC.md`; every Phase 3 visual, responsive, copy, state, and accessibility rule remains in force inside the product-screen region.

## Design System

| Property | Value |
|----------|-------|
| Tool | Existing manual shadcn-compatible canonical source plus host-owned shell composition |
| Preset | No root `components.json`; the installed consumer remains `new-york`, neutral, Tailwind v4, CSS variables, and `rsc: false` |
| Component library | Existing official shadcn primitives and native HTML; Radix only for the existing Dialog and Popover behavior |
| Icon library | Existing injectable icon slots with `lucide-react@1.20.0` defaults |
| Font | Host-provided `--font-sans`; fallback `ui-sans-serif, system-ui, sans-serif` |

The local app inherits the Phase 3 semantic variables and default light/dark values. It may add layout selectors for the shell but may not introduce a second palette, type scale, radius system, or component theme. A text wordmark, not a new image or logo dependency, identifies Afferent in v1.

No root shadcn initialization is required: the repository is the author of a static registry, and the local app proves installation from that public registry shape. Phase 4 introduces no third-party registry.

## Spacing Scale

The shell reuses the complete Phase 3 scale:

| Token | Value | Hosted-app usage |
|-------|-------|------------------|
| xs | 4px | Badge and icon gaps |
| sm | 8px | Compact navigation, account, and lifecycle metadata gaps |
| md | 16px | Default control groups, mobile gutters, notice padding |
| lg | 24px | Shell sections, sign-in card, lifecycle panel padding |
| xl | 32px | Product-region and explanatory-section gaps |
| 2xl | 48px | Major route sections and desktop gutters |
| 3xl | 64px | Signed-out introduction rhythm only |

Exceptions: 44px minimum coarse-pointer targets; 24px WCAG 2.2 minimum targets or documented spacing exception for fine pointers; one-pixel borders; two-pixel focus rings. These are sizing or rendering rules, not additional spacing tokens. Do not introduce 12px, 20px, or 40px spacing values.

Hosted layout rules:

- Shell gutters are 16px at 320–639px, 32px at 640–1023px, and at most 48px from 1024px upward.
- The shell header and lifecycle strip use 16px internal spacing; the sign-in and lifecycle recovery cards use 24px.
- The product region begins 32px after any shell-level notice. Canonical screens retain their own internal spacing without a second wrapper adding card chrome.
- The shell content width is at most 1200px. Canonical screen-specific maximum widths remain unchanged.

## Typography

Exactly the Phase 3 four sizes and two weights are permitted:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label and metadata | 14px | 400 regular or 600 semibold | 1.4 |
| Body and controls | 16px | 400 regular or 600 semibold | 1.5 |
| Section and shell heading | 20px | 600 semibold | 1.3 |
| Route display | 28px | 600 semibold | 1.2 |

The only font weights are 400 and 600. The `Afferent` wordmark is 20px semibold, route titles are 28px semibold, and shell explanatory copy is 16px regular with a maximum line length of 68 characters. Release, account, expiry, and quota metadata may use 14px. Privacy, environment, lifecycle, and quota state must never be communicated by size or weight alone.

## Color

The local shell inherits the Phase 3 60/30/10 hierarchy:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)`; light `#ffffff`, dark `#09090b` | Page background and open shell/product area |
| Secondary (30%) | `var(--card)` / `var(--muted)`; light `#f4f4f5`, dark `#18181b` | Header boundary, sign-in card, lifecycle strip, quota and recovery panels |
| Accent (10%) | `var(--primary)`; light `#1d4ed8`, dark `#60a5fa` | Current route, one route-primary CTA, unread marker, and focus ring |
| Destructive | `var(--destructive)`; light `#b91c1c`, dark `#f87171` | `Reset my sandbox`, destructive dialog title/icon, and reset failure requiring correction |

Accent is reserved for the current `Showcase` or `My sandbox` route, `Open my sandbox` or `Sign in to open my sandbox`, canonical screen-primary actions, unread notification state, release-link focus, and visible keyboard focus. The shell must not color every link or badge blue.

Showcase and sandbox do not receive competing theme colors. Their boundary is expressed by route label, page heading, environment badge, explanatory sentence, component-instance bindings, and URL—not by color alone. `Immutable showcase`, `Private sandbox`, `Preparing`, `Resetting`, `Quota reached`, and `Expired` always render as text.

All inherited contrast requirements remain: 4.5:1 for normal text, 3:1 for meaningful non-text boundaries and focus, and a visible forced-color representation.

## Information Architecture and Routes

### Stable route families

| Route | Environment | Required composition |
|-------|-------------|----------------------|
| `/` | Immutable showcase | Canonical feedback board; this is the signed-out default |
| `/feedback/:postId` | Immutable showcase | Canonical feedback detail and discussion |
| `/roadmap` | Immutable showcase | Canonical roadmap |
| `/changelog` and `/changelog/:slug` | Immutable showcase | Canonical changelog list/detail |
| `/sandbox` | Private sandbox | Sign-in gate, lifecycle preparation, or canonical sandbox feedback board |
| `/sandbox/feedback/:postId` | Private sandbox | Canonical sandbox feedback detail and discussion |
| `/sandbox/roadmap` | Private sandbox | Canonical sandbox roadmap |
| `/sandbox/changelog` and `/sandbox/changelog/:slug` | Private sandbox | Canonical sandbox changelog list/detail |
| `/sandbox/notifications` | Private sandbox | Canonical notification list |
| `/sandbox/admin` | Private sandbox | Canonical administration screen |

Unknown or stale sandbox resources render the canonical not-found state inside the sandbox shell; they never fall through to a showcase record with the same identifier. Signing out from any `/sandbox/**` route immediately removes sandbox bindings and content, then renders the sign-in gate at `/sandbox`.

### Shell anatomy

The document order is:

1. visible-on-focus `Skip to main content` link;
2. shell `header` with the text wordmark, primary environment navigation, documentation/source links, and auth/account action;
3. one environment-context region;
4. exactly one `main` containing the canonical screen or a lifecycle state;
5. compact footer with license, documentation, source, npm, and matching version.

`Showcase` and `My sandbox` are the first two primary navigation links and remain visible without opening a menu. `Documentation` and `Source` are utility links. The current environment uses `aria-current="page"` on its route link and a persistent text badge adjacent to the route title.

The local shell may link to repository documentation and source, but it does not present a separately deployed demo version or release badge. Package, registry, docs, and source-tag coherence remains a release-pipeline assertion rather than a local-runtime claim.

## Hosted Surface Contracts

### Immutable showcase

- Route heading: `Afferent showcase`.
- Environment badge: `Immutable showcase`.
- Introduction: `Browse the feedback, roadmap, and changelog experience that ships with Afferent. This shared example is read-only.`
- Primary shell CTA: `Open my sandbox`.
- The browser receives only showcase read bindings. Participation and admin bindings are not mounted.
- Canonical screens render their read-only capability state; the shell must not add disabled or decorative write controls that imply browser-side enforcement.
- No reset, usage, expiry, account-admin, or sandbox lifecycle control appears in the showcase.
- Representative seed content is realistic and deterministic; no shell control exposes seed mechanics.

### Private sandbox

- Route heading: `My private sandbox`.
- Environment badge: `Private sandbox`.
- Persistent explanation: `Only you can access this resettable demo environment. It expires after 7 days without activity and has usage limits.`
- Utility actions: `View sandbox limits`, `Reset my sandbox`, and `Sign out`.
- The sandbox renders both the canonical public participation routes and canonical admin route through sandbox-specific bindings. It never alters canonical product-screen source.
- The shell may display the authenticated visitor's safe display name or avatar. It never displays or places in markup, URLs, telemetry attributes, copy, or errors the provider user ID, Afferent actor ID, logical sandbox key, physical `scopeId`, or generation.
- Environment navigation between showcase and sandbox is a route change that replaces all bindings. No canonical query result from the prior environment remains visible while the new provider initializes.

### Sandbox lifecycle strip

The strip appears on every authenticated sandbox route above `main`. It contains:

- the `Private sandbox` badge;
- the sentence `Private, resettable, quota-limited, and removed after 7 days without activity.`;
- `View sandbox limits`;
- `Reset my sandbox`.

`View sandbox limits` opens a non-modal, keyboard-reachable disclosure or page section listing server-returned root-resource usage as `{resource}: {used} of {limit}`. It does not calculate limits in the browser. Total footprint may be summarized as `Storage footprint: {used} of {limit}` only when the server returns an exact comparable unit. No circular gauge, decorative chart, or color-only warning is introduced.

Approaching a limit does not create invented urgency. At the exact server-defined boundary, the relevant row gains the text `Limit reached`; the server's structured failure determines the matching resource and recovery actions.

## Authentication and Lifecycle States

| State | Heading | Body | Action and focus contract |
|-------|---------|------|---------------------------|
| Signed out on showcase | `Afferent showcase` | Showcase introduction | `Open my sandbox` routes to the sandbox sign-in gate |
| Sandbox sign-in gate | `Sign in to open your private sandbox` | `Sign in with Convex Auth to try the complete feedback and admin workflow in an environment only you can access.` | Primary `Sign in to open my sandbox`; secondary `Return to showcase` |
| Auth resolving | `Checking your session…` | `Your sandbox has not been opened yet.` | Polite status; no empty product screen or stale account content |
| First access / reseed | `Preparing your private sandbox…` | `We're restoring the deterministic demo content. You can start when preparation is complete.` | `aria-busy="true"` on the lifecycle region; no competing mutation controls |
| Ready | `My private sandbox` | Persistent lifecycle explanation | Canonical product route receives focus context without moving focus on background reactive updates |
| Signed out from sandbox | `Sign in to open your private sandbox` | `Your previous sandbox content is no longer available in this browser session.` | Clear watches first, then focus the sign-in heading |
| Expired on return | `Preparing a fresh private sandbox…` | `The previous sandbox expired after 7 days without activity. We're restoring the demo baseline now.` | Same inaccessible-pending-generation behavior as first access |
| Lifecycle query failure | `We couldn't open your sandbox` | `Your previous sandbox has not been changed. Try opening it again.` | `Try opening my sandbox`; secondary `Return to showcase` |

The auth provider controls credential-entry UI. The local shell provides only the entry, return, pending, failure, and account states around it. Rendering an authenticated route or the word `admin` never grants authority; each server operation resolves the current session again.

SPA route changes update the document title and move focus to the new route's `h1` only after an explicit navigation. Reactive data updates, quota refreshes, seed completion, and ordinary mutations announce through stable live regions without stealing focus.

## Reset Interaction Contract

`Reset my sandbox` is the only new destructive UI action in Phase 4.

### Confirmation

Reset opens a modal Dialog titled `Reset your private sandbox?` with this exact body:

`This removes the feedback, comments, votes, moderation work, notifications, and changelog changes in your private sandbox only. Afferent will restore the original demo content. The shared showcase and every other visitor's sandbox are not affected.`

Actions are:

- destructive primary: `Reset my sandbox`;
- neutral escape: `Keep my sandbox`.

Typed-name confirmation is not required because the affected environment is private, bounded, and restored deterministically. The dialog identifies the consequences and isolation boundary explicitly. Escape, outside dismissal, and `Keep my sandbox` restore focus to the reset trigger.

### Progress and completion

- After confirmation, close the dialog, disable the reset trigger, set the lifecycle region busy, and announce `Resetting your private sandbox…`.
- Keep the previously active generation hidden from mutation and display once reset begins. Never render a partly deleted or partly seeded product screen.
- Concurrent reset attempts coalesce into the same visible pending state; the browser never displays generation numbers.
- On success, keep focus on the stable shell reset control and announce `Sandbox restored. The original demo content is ready.` The route returns to `/sandbox` and the canonical feedback screen binds to the new active generation.
- On failure before activation, retain the previous active sandbox and render `Your sandbox wasn't reset. Your previous content is still available.` Actions: `Try resetting again` and `Return to my sandbox`.
- If activation succeeds but retired-scope cleanup continues, the user-facing reset is complete. Internal cleanup state, job IDs, scope IDs, and retries are never shown as user work.

## Quota and Rate-Limit Recovery

| Failure | Heading | Body | Actions |
|---------|---------|------|---------|
| Root-resource quota | `{Resource} limit reached` | `Your private sandbox has {used} of {limit} {resource}. Remove content or reset the sandbox to restore the demo baseline.` | `Review sandbox content`; `Reset my sandbox` |
| Total-footprint quota | `Sandbox storage limit reached` | `This private demo environment has reached its storage limit. Remove content or reset it to continue.` | `Review sandbox content`; `Reset my sandbox` |
| Participation rate limit | `Please wait before trying again` | Use the existing typed server guidance; do not invent a countdown | Existing domain-specific retry after eligibility; `View sandbox limits` only when relevant |
| Reset abuse throttle | `Please wait before resetting again` | `Resetting does not clear the activity limits for this private sandbox. Try again after the server-provided wait.` | `Return to my sandbox` |

Quota alerts are adjacent to the action that failed and summarized once in the lifecycle region. They do not erase entered form content, masquerade as product validation, or expose global storage internals. The UI offers delete/review only where an existing canonical workflow supports it; it must not add generic CRUD or a raw storage console.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Host primary CTA | `Open my sandbox` |
| Auth CTA | `Sign in to open my sandbox` |
| Showcase state | `Immutable showcase` |
| Sandbox state | `Private sandbox` |
| Sandbox empty/preparation heading | `Preparing your private sandbox…` |
| Host error | `We couldn't open your sandbox. Your previous sandbox has not been changed. Try opening it again.` |
| Destructive confirmation | `Reset your private sandbox?` with the exact reset body and actions defined above |
| Expiry statement | `Expires after 7 days without activity` |
| Quota disclosure | `View sandbox limits` |
| Version badge | `afferent v{version}` |

Shell copy may name Afferent because the host application is the product's own example. Canonical product copy remains product-neutral and dictionary-driven. Avoid `tenant`, `namespace`, `scope`, `generation`, `database`, and `multi-product` in visitor-facing text.

No action uses `Submit`, `OK`, `Save`, `Create`, `Delete`, `Retry`, or `Cancel` alone. Do not promise permanent retention, real customer hosting, shared collaboration, or a production organization.

## Responsive Layout Contract

| Width | Shell and navigation | Lifecycle and product region |
|-------|----------------------|------------------------------|
| 320–639px | Two rows: wordmark/version/account first; full-width `Showcase` and `My sandbox` links second. Utility links move to the footer. No hamburger is required for the two primary destinations. | Lifecycle strip stacks text and full-width actions. One-column product layout inherits Phase 3. No horizontal page scroll. |
| 640–767px | Wordmark/version and account share the first row; primary and utility navigation share a wrapped second row. | Lifecycle text and actions may share two rows. |
| 768–1023px | One header row when labels fit; navigation wraps before labels truncate. | Lifecycle summary and actions share one row; canonical tablet layouts remain unchanged. |
| 1024px and wider | Single horizontal header inside a 1200px maximum shell width. | Lifecycle summary left, actions right; canonical desktop layouts remain unchanged. |

At 200% zoom, the header and lifecycle strip behave as their narrow equivalent. Labels do not truncate into ambiguous icons. Product-screen breakpoints, phone card transformations, dialogs, and page-level reflow remain governed by Phase 3.

## Accessibility and Interaction Contract

- The shell owns one skip link, one `header`, and one `main`. Embedded canonical screens must be composed in their non-page-owning mode so landmarks are not duplicated.
- `Showcase`, `My sandbox`, `Documentation`, `Source`, npm version, and source commit are real links with meaningful accessible names.
- Current environment, private state, immutability, expiry, quota, auth, and reset state use text in addition to icon, border, or color.
- The reset Dialog traps focus, closes with Escape, restores focus, and retains an explicit neutral escape action. Pending reset never leaves focus inside removed generation content.
- One stable polite live region announces auth resolution, sandbox preparation, reset progress, reset success, route result readiness, and nonurgent quota updates. `role="alert"` is limited to lifecycle, reset, and quota failures requiring correction.
- Auth sign-out clears sandbox subscriptions and cached visible data before rendering the signed-out state. A second user's content must never flash during account changes.
- Shell actions meet 44 by 44 CSS pixels for coarse pointers. Focus uses the inherited two-pixel `--ring` outline with offset and remains visible in forced colors.
- Motion is limited to opacity or disclosure transitions and is removed under `prefers-reduced-motion`. No progress state depends on animation.
- Every route has a unique document title in the form `{Route} — Afferent {environment}`. Titles never include a user, scope, or generated sandbox identifier.
- Installed-artifact evidence repeats keyboard, focus restoration, 320px reflow, 200% zoom, contrast, forced colors, and axe checks against the real local app on anonymous Convex. Axe remains a regression net, not a certification claim.

## Verification Evidence Contract

| Contract | Required executable proof |
|----------|---------------------------|
| Environment boundary | Anonymous showcase route exposes only read behavior; every write/admin route is absent server-side. Sandbox routes show `Private sandbox` and require current Convex Auth. |
| Canonical UI reuse | Local-app imports resolve from registry-installed source and `afferent/react.js`; no duplicate demo product screen exists. Canonical/mirror/registry drift gates remain clean. |
| Auth transitions | Signed out → sign in → prepare → ready → sign out completes by keyboard, clears subscriptions before identity change, manages route-title/focus, and never flashes sandbox content to another account. |
| Reset | Dialog copy, isolation statement, focus restoration, pending announcement, no partial generation, success baseline, retained-old-generation failure, and concurrent coalescing are asserted against real Convex. |
| Expiry | A seven-day-expired sandbox renders the fresh-preparation copy, restores the deterministic baseline, and never exposes retired data. |
| Quota/rate | Exact-limit and one-over failures name the resource, preserve form state, offer valid recovery, and never imply reset bypasses rate limits. |
| Responsive shell | Showcase, sign-in, ready sandbox, quota failure, reset dialog, and reset pending pass at 320x800, 768x1024, 1280x800, and 200% zoom without page-level horizontal overflow. |
| Accessibility | Keyboard-only journey, Dialog containment/restoration, polite/alert semantics, forced-color visibility, contrast, target size, and axe checks run against the registry-installed local candidate. |
| Bootstrap integrity | The local shell becomes reachable only after the anonymous Convex backend, ephemeral auth configuration, deterministic seed, and Vite app are ready; failures provide actionable terminal guidance. |
| Two-user isolation | Simultaneous browser contexts with colliding content never receive each other's route data, quota state, notifications, reset effect, lifecycle copy, or reactive update. |

Evidence uses deterministic seed content and stable scenario identifiers. It normalizes timestamps, temporary local backend names, ports, and process IDs while retaining artifact digest, source commit, backend kind, environment label, and expected/actual interaction result.
