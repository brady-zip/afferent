<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Verified owner -> logical sandbox | Provider identity must be domain-separated and never persisted or returned as browser authority. |
| Logical sandbox -> physical generation | Reset/expiry must switch atomically only after complete seeding. |
| Internal seeder -> component operations | Seed orchestration has broad domain authority but must remain internal, bounded, scoped, and idempotent. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-09 | Spoofing | logical sandbox owner | critical | mitigate | Derive owner from current Convex Auth on every entry and expose no owner/scope/generation validator. |
| T-04-10 | Tampering | reset activation | critical | mitigate | Seed a pending physical scope completely and use leased compare-and-set active-pointer activation. |
| T-04-11 | Information Disclosure | lifecycle DTO/errors | high | mitigate | Return a closed safe state vocabulary and test markup/serialized results for forbidden identifiers. |
| T-04-12 | Denial of Service | concurrent ensure/reset | high | mitigate | Coalesce requests behind one leased pending generation and bound each seed step. |
| T-04-13 | Repudiation | deterministic seed | medium | mitigate | Persist seed version/step state and assert exact semantic manifest counts/links across retries. |
</threat_model>
