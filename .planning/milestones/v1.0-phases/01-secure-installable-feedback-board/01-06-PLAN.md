## Trust Boundaries

| Boundary | Description |
|---|---|
| Provider component/session -> host fixture | Provider identity is trusted only after the current server helper validates it. |
| Host fixture -> Afferent client | Only the minimal provider-neutral actor snapshot crosses this boundary. |
| Browser intent -> host function | Browser arguments remain incapable of supplying actor, admin, or scope authority. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-25 | Spoofing | Better Auth fixture | critical | mitigate | Compile directly against `getAuthUser` and normalize its stable returned document ID. |
| T-01-26 | Information Disclosure | Better Auth adapter | high | mitigate | Map only stable ID plus optional display fields; static tests reject provider/private fields. |
| T-01-27 | Elevation of Privilege | host context widening | critical | mitigate | Widen server context capabilities only; retain exact authority-free browser validators. |
| T-01-28 | Tampering | fixture compilation | high | mitigate | Independent strict tsconfigs resolve package declarations and fail the automated gate on drift. |
| T-01-SC | Tampering | npm installs | high | mitigate | No package install occurs; the previously approved exact dependency set and lockfile remain unchanged. |
</threat_model>
