## Trust Boundaries

| Boundary | Description |
|---|---|
| Auth provider/session → host adapter | Provider data is trusted only through current server verification helpers. |
| Browser → provider fixture wrapper | Client intent and forged extras must never become actor/admin/scope authority. |
| Package exports → consumer | Export maps and declarations must expose only supported provider-neutral contracts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-20 | Spoofing | provider adapters | critical | mitigate | Use current server helpers on every call and namespace stable non-session identifiers. |
| T-01-21 | Elevation of Privilege | admin callbacks | critical | mitigate | Separate host-owned authorization from identity/provider claims; conformance spies prove denial before component call. |
| T-01-22 | Information Disclosure | provider normalization | high | mitigate | Normalize only external key and optional display fields; structural tests reject provider/private shapes. |
| T-01-23 | Tampering | browser forged args | critical | mitigate | Exact browser validators omit authority fields and the shared forgery matrix runs for all providers. |
| T-01-24 | Tampering | packed artifact | high | mitigate | Tarball-only external fixture, export/declaration linters, fresh install, and source-root resolution rejection. |
| T-01-SC | Tampering | npm installs | high | mitigate | Provider/test packages use Plan 01-01 reviewed exact versions as fixture-only dependencies with lockfile. |
</threat_model>
