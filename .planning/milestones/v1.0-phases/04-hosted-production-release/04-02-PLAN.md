<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser -> hosted Convex functions | Browser intents may contain resource IDs and pagination only, never actor/admin/scope/generation authority. |
| Convex Auth -> host wrapper | Only the verified server helper result may become the provider-neutral actor and logical sandbox owner. |
| Host wrapper -> two Afferent instances | Showcase and sandbox component references must never be interchanged. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-05 | Spoofing | sandbox actor resolution | critical | mitigate | Resolve `getAuthUserId` on every call and reject all browser authority-shaped fields. |
| T-04-06 | Elevation of Privilege | sandbox admin resolver | critical | mitigate | Independently re-resolve current authentication inside every admin capability call. |
| T-04-07 | Tampering | showcase bindings | high | mitigate | Export reads only and add static/host tests that fail on any mounted showcase mutation. |
| T-04-08 | Information Disclosure | component instance routing | high | mitigate | Use distinct generated references and cross-instance forged-ID tests with not-found-equivalent behavior. |
| T-04-SC | Tampering | auth dependencies | high | mitigate | Use the already audited exact Convex Auth packages and revalidate official package/API metadata before code changes. |
</threat_model>
