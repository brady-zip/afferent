<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Repository source -> npm tarball | Only declared built artifacts, types, license, and metadata may become the consumer package. |
| npm tarball -> clean Convex consumer | Workspace resolution must not hide a missing export, dependency, generated component type, or test helper. |
| Registry/npm metadata -> release identity | Package name and compatible version must refer to the intended release, not a newly occupied name or moving tag. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04-01 | Tampering | package export map | high | mitigate | Assert every runtime/types target against the one packed tarball and reject raw-TypeScript public targets. |
| T-04-02 | Spoofing | npm package name | high | mitigate | Query the registry immediately before publish and fail on unexpected ownership instead of renaming automatically. |
| T-04-03 | Repudiation | release-candidate evidence | high | mitigate | Reuse one tarball path across inspection, clean installation, publint, and ATTW with a normalized transcript. |
| T-04-04 | Information Disclosure | tarball contents | medium | mitigate | Enforce the package `files` allowlist and reject repository-only/configuration files not required by consumers. |
| T-04-SC | Tampering | npm dependency graph | high | mitigate | This plan installs no new package; existing audited exact dependencies remain unchanged. |
</threat_model>
