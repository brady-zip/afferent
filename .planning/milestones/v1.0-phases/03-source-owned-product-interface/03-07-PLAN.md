## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser confirmations -> trusted host mutations | Confirmation proves user intent only; the host still derives identity, admin permission, and scope on every operation. |
| Controlled phone navigation -> admin presentation | The host controls presentation state but cannot supply authority or replace server capability truth. |
| Canonical copied source -> generated registry consumer | Interaction and security corrections must reach installed source without hand-edited output drift. |

| T-03-24 | Repudiation / Tampering | consequential admin actions | high | mitigate | Exact consequence dialogs, action-key pending/error/reset state, duplicate-submit blocking, and mounted no-mutation-before-confirmation tests. |
| T-03-25 | Elevation of Privilege | controlled admin presentation | critical | mitigate | Accept only navigation intent; keep capability and every mutation in existing trusted host/headless contracts and statically reject authority props/imports. |
| T-03-26 | Tampering | generated UI distribution | high | mitigate | Catalog registration, deterministic regeneration, schema/hash/byte checks, and real clean installed-source build. |
