<decisions>
## Implementation Decisions

### Admin Feedback Reads and Moderation Truth
- **D-01:** Add a versioned `AdminFeedbackPostDto` and `AdminFeedbackPageDto` rather than widening public feedback reads with hidden lifecycle truth. The admin DTO carries the public presentation fields plus exact `discussionLocked`, `archived`, and lifecycle/merge disposition required to distinguish actionable active, archived, withdrawn, and merged records.
- **D-02:** Add a bounded admin feedback queue ordered by the existing scope-leading visibility/created index with a closed `visibility: "visible" | "hidden"` filter. Hidden results include archived and other non-public lifecycle records, and each row's disposition prevents presenting restore or moderation actions incorrectly.
- **D-03:** Add a direct scoped admin post lookup so an authorized admin can reopen a known hidden/archived record. Both reads are authorized in the trusted host wrapper on every call; non-admin denial occurs before the component query is invoked.
- **D-04:** Browser bindings accept only resource/filter/pagination intent plus `sessionGeneration`. They never accept `isAdmin`, actor identity, scope, moderation truth, or visibility authority.

### Administrative Changelog Read
- **D-05:** Add a scope-leading `changelogEntries.by_scope_created` index and a bounded newest-first admin query that pages drafts, published entries, and previously published/unpublished entries together.
- **D-06:** Add `AdminChangelogPageDto` version 1, the corresponding trusted client capability and binding, and a headless paginated admin changelog hook with explicit unsupported, auth/loading, not-authorized, empty, ready, loading-more, and error states.
- **D-07:** Replace `AdminChangelogEntryDto.postIds` with ordered `links: ChangelogLinkedPostDto[]` containing stable opaque post ID, title, and status summary; bump the admin entry DTO from version 1 to 2. Resolve links server-side with canonical merge normalization and no hook/UI N+1 reads.

### Readable Historical Activity
- **D-08:** Replace `PostActivityDto`'s `fromBoardId`, `toBoardId`, `tagId`, and `changelogEntryId` presentation fields with closed readable references: boards expose name and slug, tags expose name, and changelog entries expose title and public slug. Component-internal relation IDs never cross this DTO.
- **D-09:** Snapshot these readable fields when activity is appended, before a tag can be deleted or a changelog can be unpublished. Preserve the internal foreign IDs only for component invariants/maintenance, not public projection.
- **D-10:** For legacy rows without snapshots, resolve an existing same-scope referent on read; if it is gone, return a stable readable unavailable/deleted label rather than exposing its ID. Unlisted/unpublished records remain readable to the authorized admin.
- **D-11:** Bump `PostActivityDto` and `PostActivityPageDto` from version 1 to 2 across types, validators, bindings, generated refs, fixtures, and tests.

### Authority, Headless Behavior, and Verification
- **D-12:** Reuse `authorizeAdmin(ctx)` in every trusted host read and prove denial prevents component invocation. The component remains isolated from host `ctx.auth`; browser capability display is never enforcement.
- **D-13:** Headless hooks surface server DTOs and paginated state verbatim; they do not join boards, tags, posts, or changelog entries in the browser.
- **D-14:** Start red with all five locked gaps, two-scope/non-admin/spoofing matrices, index/no-scan guards, deleted/unlisted referents, and exact DTO/page version transitions. Finish with focused component/headless/packed tests and the complete Phase 2 regression.

### the agent's Discretion
- Exact exported hook/helper names and internal file decomposition are flexible when the five gaps, closed DTOs, server-side joins, and auth boundary remain exact.
- Default page sizes may follow existing 20-item admin/activity conventions; validators must retain the established 1..50 bound.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- Posts already have `by_scope_visibility_created`, `discussionLocked`, `archivedAt`, `lifecycleState`, and merge state; the missing piece is an admin-only projection and read surface.
- `requireAdmin` behavior in `src/client/internal.ts` already guards every admin capability before calling component functions.
- `toChangelogLinkedPostDto` already produces the id/title/status summary needed by admin changelog entries, and canonical link resolution already exists.
- `appendPostActivity` is the single activity write seam and can snapshot readable referents consistently before destructive/unlisting changes.

### Established Patterns
- Component admin operations still rely on the host as the security boundary; no client-provided `isAdmin` or component access to host auth is allowed.
- React uses injected function references and closed paginated watch states with session-generation fencing.
- Scoped indexes and validators bound all list reads; presentation joins occur server-side and never through UI N+1 queries.

### Integration Points
- `src/component/admin/posts.ts` and a focused admin read module own list/detail projection; `src/client/internal.ts`, contracts, and React bindings carry the trusted surface.
- `src/component/admin/changelog.ts`, `src/component/model/changelog.ts`, and `src/component/schema.ts` own all-state changelog pagination and linked summaries.
- `src/component/model/activity.ts`, activity producers, and the schema own snapshot-at-write plus legacy fallback projection.
- Phase 3 Plan `03-04` consumes these admin queue, moderation, changelog, and activity hooks directly.

</code_context>
